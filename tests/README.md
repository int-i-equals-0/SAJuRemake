# Тесты

Без зависимостей и сборки: игра поднимается в изолированном контексте Node
с заглушками браузера, кадры прокручиваются вручную.

```
node tests/run.js          # все наборы
node tests/jump.test.js    # один набор
```

| Набор | Проверок | О чём |
|---|---|---|
| `clear.test.js` | 10 | связные группы одного цвета, полный нижний ряд, формулы очков |
| `push.test.js` | 10 | сила толкания у трёх персонажей, тёмный блок, край поля |
| `jump.test.js` | 20 | прыжок вверх-вбок с толканием — дословно примеры владельца |
| `bonus.test.js` | 29 | все бонусы, кому что выпадает, пороги открытия персонажей |
| `physics.test.js` | 40 | падение, удар каской, сдвиги, возрождение, модель ввода |
| `stress.test.js` | 4 прогона | 7500 кадров случайной игры, инварианты состояния |

## Стенд

`harness.js` даёт две вещи:

- `makeGame({ char, setup, raw })` — поднимает игру, по умолчанию чистит поле,
  останавливает кран и переводит в `playing`. Возвращает помощники: `run` и
  `get` для кода внутри игры, `key` для клавиатурных событий, `frames(n)` для
  прокрутки, `col(c)` и `snap()` для чтения состояния.
- `suite(name)` — счётчик проверок с печатью и кодом возврата.

Тест видит все внутренности игры: `grid`, `worker`, `planMove`, `useBonus` и
прочее. Отдельного экспорта из `js/game.js` не требуется.

## Как проверять сами тесты

Набор бесполезен, если не умеет падать. Поэтому полезно нарочно сломать игру
и убедиться, что это замечено. Три проверенные мутации:

| Мутация | Кто ловит |
|---|---|
| `MATCH_MIN` 3 → 4 | `clear.test.js` |
| скорость падения грузчика вдвое выше | `physics.test.js` |
| автоповтор клавиши кладётся в очередь | `physics.test.js` |

Третья мутация поначалу **не ловилась**: тесты ввода дёргали `action()`
напрямую и обходили обработчик клавиш. Пришлось добавить проверку, которая
шлёт настоящие события `keydown` без `keyup`, как это делает браузер.
